## What's free

One **Sandbox** cluster per account: a single node with up to 2 vCPUs, 4 GB memory and 10 GB
storage, 15 connections, 500 tables or 12.5 million rows, no backups, on AWS or GCP. It is paused
after 10 days without activity and deleted after 15. The docs contradict themselves on whether
you can pause a Sandbox by hand. Whether a card is needed to sign up is unverified. See the
[Sandbox docs](https://docs.yugabyte.com/preview/yugabyte-cloud/cloud-basics/create-clusters/create-clusters-free/).

The stack checks the cluster count (1); more needs `acknowledge_billable_resources = true`, though
this stack only ever makes the free tier.

## API key

Make a key in YugabyteDB Aeon (Security > API Keys) and put it in `.freelunch/.env`:

```bash
YBM_API_KEY=...
# YBM_API_KEY=op://Private/Yugabyte/api-key
```

## Usage

```bash
freelunch init yugabyte
cp .freelunch/yugabyte/terraform.tfvars.example .freelunch/yugabyte/terraform.tfvars
freelunch apply yugabyte
freelunch output yugabyte -json database_credentials   # { "yugabyte-main": { password, url } }
```

Each entry in `databases` is a Sandbox cluster `<name_prefix>-<name>` with an admin user (default
`admin`) and a generated password. The stack outputs the
[database contract](../../docs/architecture.md#database-contract): YSQL (Postgres-compatible) on
port 5433, database `yugabyte`, behavior `pauses`.

## Caveats

- A Sandbox is reachable only through an IP allow list. Set `allow_cidrs`; with it empty no allow
  list is made and nothing can connect.
- The password is generated by Terraform and kept in the state, so keep the state private.
- The host is read from the cluster's `endpoints` attribute; the first one is used.
- Nothing here has run against a real account: the tests plan against a mocked API.
